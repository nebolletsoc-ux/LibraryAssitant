--- Technical debt (added after TBR rework, September 2026) ---
No automated test suite, high, All verification of add_book, import-csv, check-all, list filtering, and the recent search/filter bugs was done with ad hoc manual scripts and browser checks. Add a real pytest suite covering these endpoints and the frontend filter logic so regressions are caught automatically instead of by manual QA.
Availability scan concurrency, PARTIAL, check-all now runs concurrently (ThreadPoolExecutor, 8 workers) so a ~150-book scan completes in the time a single library sweep used to take (was 500+ s, now quick). Remaining: progress reporting (per-book title or a live "X/Y scanned" during the run, not just after) and a cancel button — ties to "Informative status bar" above.
Duplicate Book rows for the same title, medium, Different search results/editions (e.g. "The Lager Queen of Minnesota" vs "The Lager Queen of Minnesota: A Novel") can create separate Book rows with separate synthetic ISBNs, so the same book can appear twice in the TBR list. Needs title normalization or a merge/dedupe step before creating a new Book.
Single hardcoded user (user_id=1), medium, Every model and endpoint assumes one user. Any real multi-user deployment needs an auth layer and per-user scoping instead of the hardcoded default.
No CSRF protection / minimal auth, medium, State-changing endpoints (POST/PATCH/DELETE) are only gated by an optional shared APP_PASSWORD env var with no CSRF protection. Fine for personal/local use; needs hardening before any public multi-user deployment.
Open Library search has no caching or backoff, medium, Rapid repeated searches during testing produced real 503s from Open Library. The app now surfaces a clear "temporarily unavailable" message, but there is no client-side rate limiting, retry/backoff, or short-lived caching of recent queries.
Redundant "Hoopla · hoopla" label, RESOLVED, In the TBR detail modal, Hoopla availability rows showed "Hoopla · hoopla" since library and provider are both effectively "hoopla". providerLabel() now returns a single "Hoopla" for Hoopla rows (verified in headless Chrome). Related: Hoopla rows produced duplicates because Oakland and Berkeley both tag the shared Hoopla catalog as library="hoopla" — now deduped to one row per format in the detail modal (see new dedupe item below).
Legacy CSV-scan app still present alongside TBR view, low, templates/index.html and the "old code/" folder are still in the repo alongside the newer TBR view (templates/tbr.html). Decide whether to retire the legacy view or keep it as a fallback, to reduce duplicate UI/maintenance surface.
No pagination/virtualization for large TBR lists, low, Current lists of 150+ books render fine, but there is no pagination or virtualization if a user's list grows much larger.
